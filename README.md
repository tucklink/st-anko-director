# 安科导游（st-anko-director）

SillyTavern 前端扩展：内置一个「导演」agent，把一个回合推演成**大纲**，由插件负责**投骰**，再把大纲交给正文 AI 演出。

> 一句话分工：**导演只写骨架 + 摆骰子，插件真随机投骰并回填，演员写正文。**

## 它解决的问题

- AI 自己编骰点 ✗ → 骰子由插件真随机生成，值是**既成事实**，模型不许改
- 长对话里导演"看不到上下文" ✗ → 上下文简报 + 世界书注入
- 选项表写着写着散掉 ✗ → 固定 6 行结构（1-2 纯正面 / 3-4 好坏参半 / 5-6 埋伏笔 / 7-8 揭旧伏笔 / 9 玩梗 / 10 大成功·大失败）

## 安装

```bash
# 进到酒馆的第三方扩展目录
cd SillyTavern/public/scripts/extensions/third-party
git clone https://github.com/tucklink/st-anko-director.git
```
（或者直接把仓库目录放进 `third-party/st-anko-director`；目录名要保持一致，`index.js` 里的 `EXTENSION_PATH` 依赖它）
2. 重启 / 刷新酒馆，到「扩展」里启用 **安科导游**
3. 面板里先点「读取当前预设」核对预设，再「推演本回合」

## 怎么用

- **推演本回合**：让导演跑一个回合，大纲写进输入框
- **续推一幕 / 撤回上一幕**：接着前情往下推 / 退回一版大纲
- **安价一轮**：从安价池里均等抽一个选项
- **车卡**：给默认八项属性各投一次 1d100
- **常驻浮窗**：把面板搬成屏幕上可拖动的小窗，边聊边看骰点

# 安科导游 · st-anko-director

SillyTavern（酒馆）前端扩展。**让酒馆能跑安科**：插件扮演「骰子神」，内置一个导演 agent 替你把一个回合推演完。

分工是死的：

| 角色 | 是谁 | 职责 |
| --- | --- | --- |
| 导游 / GM | 插件里的**导演 agent** | 写大纲、决定"哪里需要骰"、解释骰点、产出玩家发言 |
| 骰子神 | **插件本体** | 真随机投骰，agent 无权改动结果 |
| 演员 | 主聊天（你的角色卡 + 提示词） | 按大纲演出正文 |

> **红线：骰子值只能由插件生成。** agent 不许自己编点数 —— 这是整个插件存在的理由。

## 它是怎么工作的

```
你写一句「我去码头打听消息」
        ↓
导演 agent 开始写大纲，写到需要随机的地方写下骰子表达式就停笔：
        我把行李寄在旅店，第二天清晨动身去码头。水路走了1d3天⌷
        ↓
插件在那一处接管：投骰 → 原地替换 → 把定稿喂回去让它接着写
        我把行李寄在旅店，第二天清晨动身去码头。水路走了【1d3=2】天，……
        ↓
大纲写完（过程中所有骰点都真投过、都记在日志里）
        ↓
写进输入框 —— 你还能改，改完按发送
        ↓
主聊天按大纲演出正文
```

**"AI 停住等骰子"是效果，不是机制。** 实现上模型其实还在往下写，是插件在**第一个骰子表达式**处截断、丢掉后面的内容，投完骰再把定稿喂回去续写。所以模型不听话也不会出错，只是多烧一点 token。

> 续写默认走**内嵌**：把已定稿文本放进用户消息里，让模型接着写，再用「回声剥离」去掉它可能重复的部分。
> **不用 `prefill`** 是因为它会变成一条 assistant 消息，而 **Gemini 明确拒绝「请求以模型回合结尾」**
> （HTTP 400 `Requests ending with a model turn are not supported`）。
> 内嵌方式所有 API 都能跑，前缀缓存照样有效。如果你的 API 支持（OpenAI 等），可以打开面板里的「用 prefill 续写」。

## 骰子文法

**支持**：`NdM`、`+` / `-`、`X` 或 `*`（乘）、`k`（取最大的 n 颗）。

```
1d100   3d6+2   1d6+1d4-1   3d6k2   3d6*5+2
```

数量 1–100、面数 1–1000，**越界直接报错，不静默截断**。

**不做**（碰到会给可读报错，不装作没看见）：`#` 多轮掷骰、`b`/`p` 奖励惩罚骰、`h` 暗骰、
`w`/`ww` 骰池、括号、除法、轮盘骰。

**随机源是 `crypto.getRandomValues()` + 拒绝采样，不是 `Math.random()`** —— 骰子是这个插件的立身之本。

## 判定规则（双轨）

**轨道 A：属性检定（COC 房规 3）**

| 骰值 | 判定 |
| --- | --- |
| 1–5 | 大成功 |
| 96–100 | 大失败 |
| ≤ 成功率/5 | 极难成功 |
| ≤ 成功率/2 | 困难成功 |
| ≤ 成功率 | 成功 |
| 其余 | 失败 |

**轨道 B：选项骰（孔明式，国内主流）**

```
投 1d10
├─ 1..9 → 直接取第 N 项（重复项 = 加权，行数即权重）
└─ 10   → 投 1d2 定大成功(1)/大失败(2)
          └─ 再投 1d10 查效果表
              └─ 效果骰又出 10 → 双重大成功/大失败（最多嵌套 2 层，再往上记「传奇」）
```

两条配套规矩（都是实跑定下来的）：

- **连投由插件做，模型不写。** 投出 10 之后插件会自动接一个 1d2，一次性给出
  `【1d10=10 → 1d2=2（大失败）】` —— 模型**不要**自己再写一个 `1d2` 去请求。
- **大成功/大失败的连投与它带来的效果表，不占骰点预算**（预算 = 面板里的「轮数上限」，见下）。
  那是骰子自己要求的，躲不掉。代码里也一样：欠着效果表时会**额外给一轮**（最多 2 轮），
  不占轮数上限 —— 否则额度一满，效果表就投不出来，后果就变成模型自己编的了。
  **模型投出大成功/大失败却不投效果表时，插件会把它打回去补投。**

## 内联骰子的写法

四种场合（prompt 里已经把这些规则教给模型了）：

| 场合 | 模型怎么写 | 插件替换成 |
| --- | --- | --- |
| 纯数值 | `水路走了1d3天` | `水路走了【1d3=2】天` |
| 选项 / 查表 | 表头用**文字**（「选项骰十项」），**每项独占一行**、行首是号数或区间，最后一行 `→ 1d10` | `→ 【1d10=7】`，而且**插件会自动在命中行末尾打 `♛`** |
| 属性检定 | `1d100【话术40】` | `【1d100=68 / 话术40 → 失败】` |
| 选项注解 | `1d10【选项】` | `【1d10=10 → 1d2=2（大失败）】` |

**四条铁律**（后两条是写测试时踩出来的真问题）：

1. 必须是可解析的字面量，不许写"一到三天""看运气"。
2. 已经投过、带 `【】` 的结果**锁定**，不许回头改。
3. 骰值影响后文时那个表达式**单独写、写完停笔**；独立项（批量生成 NPC）可以一次写多个。
4. **一个表达式只写一次**：
   - 表头别写 `（1d10）：` —— 表头里出现骰子表达式，插件会**真去投它**，
     结果变成 `（【1d10=3】）：` 这样一行奇怪的标题（实测如此）。
   - 别写 `（1d100，话术 40）→ 1d100` —— 两个表达式会被**各投一次**。

## 选项表的命中标注（插件做的，不是 AI 做的）

选项骰投完之后，读者最想知道"投中了哪一行"。AI 经常忘了标或者标错行 ——
所以**这件事由插件做**：谁投的骰子，谁负责标结果。

```
先去哪边打听 —— 选项骰十项：
1 酒馆
2-3 货栈          ← 同一条走向占多行 = 加权（孔明式原本就是这么写的）
4-5 码头管事 ♛    ← 插件打的（投出 7 时标在别的行，这里是示意）
6 酒馆后巷
7 治所告示墙
8-9 渡口船夫
10 【1D2】大成功/大失败
→ 【1d10=7】        ← 骰子本身保留
```

**十项表就是十行**，而且**各号位的分工是定死的**：

| 号位 | 内容 |
| --- | --- |
| **1–8** | **可行走向** —— 前几项偏「去哪、做什么」的具体行动，后几项偏「事情闹多大」，整体是一条**从平到炸**的斜线。一项最多两句话 |
| **9** | **玩梗项** —— 明显不属于这个世界观或这个时间点（别的作品的来客、不合时宜的东西、第四面墙被捅破）。**这是整张表的张力来源，也是玩家最想投中的那一格** |
| **10** | 固定 `10 【1D2】大成功/大失败`，投中后插件自动接投 1d2 |
| 权重 | 同一个走向**可以占多行**（`2-3`＝占两格＝加权），但**一张表至少要有 5 条不同走向** |

插件也认 `1-3` 这种区间压缩写法（容错），但**默认按十行要求 AI 写** ——
压成三四行的话，"十项表"就只剩三个选项了。

- 只对带 `【选项】` 注解的骰子打标 —— **普通 `1d10`（伤害之类）绝不会去标任何表**
- 从结果往回读，认出"每项独占一行、从 1 连续铺满"的表格，再算骰值落在哪一段
- **认不出来就什么都不做**，宁可不标也不改坏正文。两道闸：
  1. 行首号数必须**从 1 连续铺满**（有洞、有重叠、不从 1 开始都拒绝）
  2. 还要上面那行像表头（含「选项/骰/表/项」或以冒号结尾），或者行数 ≥5，或者表就在正文开头
- 投出最后一项（大成功/大失败）时，标在第 10 行；已经标过的不叠第二个
- 符号可换、可关：面板里的「选项骰命中行的标记符号」，留空即关闭

> 为什么这么谨慎：正文里出现 `1 走吧 / 2 留下` 这种编号列表很常见，
> 光靠"编号连续"分不出它和选项表 —— 所以加了表头这道闸（这是写测试时踩出来的）。

### 排障：症状 → 原因

| 症状 | 原因 | 怎么办 |
| --- | --- | --- |
| **选项表上没有 ♛**，而且投出 10 之后 AI 自己又写了个 `1d2` | 请求行漏了注解，写成了裸 `→ 1d10` —— 插件把它当普通投骰了，所以既不连投 1d2 也不打标 | 请求行必须写 `→ 1d10【选项】`。这是**唯一**区分"选项骰"和"伤害骰"的方式，漏了功能就没了 |
| 大纲停在一个没解释的骰子上（结尾是 `→ 【1d10=3】` 就没了） | 轮数上限被打满，投完最后一颗没轮次解释了 | 最后一轮现在会自动禁止再开新骰子；如果这一回合特别长，把「轮数上限」调大（默认 12，可到 50） |
| 表里的行没识别出来 | 表格写成了单行（`1-3 酒馆 4-6 货栈 …`） | 必须**每项独占一行**。单行排版定位不到具体某一行，打不了标 |
| 骰子结果是 `→ 【1d10=7】`（箭头后带空格） | 这是正常的 —— 替换只覆盖 `1d10【选项】` 本身，箭头和空格是 AI 写的，原样保留 | 不用管 |
| **只推演出第一轮就停了**，输入框里只有第一颗骰子的内容 | 第二轮开始 API 报错了（限流最常见）。插件会把已经定稿的部分交出来 —— 这是故意的，半份大纲比什么都没有有用 | 看提示条和 `/anko last`。**限流/超时会自动重试 3 次**（1.5s、3s 退避）；还是失败就说明确实被限住了，等一会儿再推，或把模型换成不那么容易限流的 |
| **轮数没跑满就结束了**（比如设 6 轮，第 4 轮就停） | **这多半是正常的**：轮数上限是**上限**不是指标。模型某一轮**没再请求骰子**，就说明它认为这一回合演完了，插件据此收尾。另一种是"卡住"（连续几轮没新内容）或出错 | 收工后「进度」那一行会**写明是哪种**：`这一回合演完了：推演 4 轮（模型某一轮没再请求骰子，自己收的尾）` / `到轮数上限收尾…` / `卡住了，提前结束…`。想看详细过程用 `/anko last` |
| **勾了「发送前自动推演」却什么都没发生** | 以前这里会把失败**静默吞掉**（`quiet` 连错误提示一起吞了），所以看不出是没跑还是跑了失败 | 已修：失败一定会弹提示。用 `/anko last` 看逐轮记录 —— 是"根本没跑"还是"跑到第 N 轮断了"，一目了然 |
| 面板上出现**红色警告行** | 两种情况：某张选项表**没认出命中行**（多半是表格写成了一行），或者定稿里**还剩解析不过去的骰子片段**（如 `3d6k4`） | 按警告原文改：表格改成"每项独占一行"；坏片段是模型写错了语法，重推一次即可 |
| **每次推演都从开场重来**（"再点一次也只推演第一楼"） | 大纲只写在**输入框**里，没发送的话聊天记录里就没有这一回合 —— 导演看不见前情，只能从头推 | 已修：插件记着最近 3 份大纲当前情（见〈连续推演与前情记忆〉）。`/anko story` 可以查看 |
| 投出大成功/大失败，但后果是 AI 自己编的 | 模型没投效果表就往下写了 | 已修：插件会把这一轮**打回去补投**效果表；欠着效果表时还会额外给一轮，不占轮数预算 |
| 面板上出现红色警告行 | 两种情况：**某张选项表没认出命中行**（多半是表格写成了一行），或**定稿里还剩解析不过去的骰子片段**（如 `3d6k4`） | 按警告原文改：表格改成"每项独占一行"；坏片段是模型写错了语法，重推一次即可 |

## 连续推演与前情记忆

**这是插件最容易被误解的地方。** 大纲是写进**输入框**的，不是写进聊天记录的：

```
你打字「我去码头」→ 点「推演本回合」→ 大纲出现在输入框里 → 你（可以改）→ 发送
```

所以如果**你没发送**就再点一次「推演本回合」，插件必须知道"上一幕演到哪了" ——
否则它只能看见旧聊天记录，于是**每次都从头推演开场**。

插件为此记着**最近 3 份大纲**（存在这个聊天的存档里，切聊天不串台）：

- 下一次推演的上下文简报里会带上〈# 已经推演过的前情〉，并注明**不要重演、不要复述**
- **已经发送进聊天记录的那份不会重复喂** —— 聊天记录里本来就有，再喂一遍既浪费 token 又会让模型爱复述
- 想看 / 清空：`/anko story`、`/anko story clear`

> 前情从**结尾**截断保留：接续点在结尾，开头丢了顶多少点背景，结尾丢了就直接接不上。

### 「推演本回合」按钮只做一件事

**推演输入框里那句话。** 没有隐藏行为：

| 输入框状态 | 按钮行为 |
| --- | --- |
| 有玩家输入 | 推演它，大纲写回输入框 |
| 空着 | 提示「先写一句玩家想做什么」（**不会**偷偷接着往下推） |
| 还留着上一次的大纲 | 提示「先把它发送出去，或改完再发」（**不会**把大纲当成玩家输入再推一遍） |

想**不写输入就直接往下推一幕**，用明确的命令：

```
/anko continue
```

> 为什么专门做成命令：早先版本写成"输入框空着点按钮就自动续推"，结果按钮的含义取决于隐藏状态 ——
> 用户得**连点两次**才能推进，第二次点还可能把上一份大纲当成新输入重新推一遍。那是胡闹，已删掉。

## 常驻浮窗与导入导出

**常驻浮窗**：面板本来在右侧「扩展设置」里，要翻抽屉才能看见。点面板上的「常驻浮窗」
（或 `/anko float`）会把它**搬到屏幕上的一个小窗口**里 —— 位置可拖、位置会被记住、点 `⇱` 收回侧栏。
边聊边看骰点日志、属性、战斗状态，不用来回翻面板。

> 为什么自己写浮窗、不用酒馆的 `Popup`：`Popup` 是**模态**的，会挡住聊天 ——
> 而"边聊边看"恰恰要求不挡。自己写也少依赖一层版本相关的 API。
> 窗口刻意做小、`z-index` 也刻意不顶到 9999（规范 C8 记着"整屏覆盖 + 高 z-index 会让 iOS 上按钮点不动"），
> 窄屏下自动占满宽度。

**导入导出**（换设备、备份、把角色属性分享给别人）：

| 动作 | 面板 | 命令 |
| --- | --- | --- |
| 导出 | 「导出 JSON」（范围由上面的下拉决定） | `/anko export [all\|attrs\|settings]` |
| 导入 | 「导入 JSON」开文件选择器 | `/anko import`，或 `/anko import {…JSON…}` 直接贴 |

- **属性** = 当前聊天的属性表、自定义随机表、安价池、生死状态；**预设** = 扩展设置（轮数上限、标记符号、注入模板、各开关…）
- 导出的文件带 `kind: "anko-director-export"` 标记，**导入时只认这个标记** —— 拿别的 JSON 来会明确拒绝
- 导入的属性会**覆盖当前聊天**，预设会**覆盖扩展设置**；坏数据不会写进去
  （属性走 `migrateState` 校验，设置逐项做类型检查、未知键直接丢弃）

## 锁死正文格式（默认就开着，比世界书管用）

**插件把大纲排好**（列表 + 骰子 + ♛）之后，主聊天 AI 写正文时**仍可能把格式打散** ——
删掉列表、把 ♛ 抹了、把骰子改个数值，都很常见。得给它一条硬约束。

**这件事插件自己做了，不用你配世界书。** 默认开启「锁死骰子格式」：

| | 世界书条目 | 插件的格式约束（默认） |
| --- | --- | --- |
| 注入位置 | 通常在角色定义区，**离生成点很远** | **depth 0** —— 紧贴生成点，约束力最强 |
| 触发方式 | 要**命中关键词**才注入，没命中就完全不起作用 | 只判断"最近几条消息里有没有骰子"，有就注入 |
| 代价 | 常驻条目会一直占 token | **有骰子才注入**，平时一个 token 都不占 |
| 关闭方式 | 手动删条目 | 面板上一个勾选框 |

注入的内容（`src/prompts.js` 的 `FORMAT_LOCK_TEXT`）：

```
【格式约束 —— 必须遵守】
上一条消息里的骰子内容是已经投好的既成事实。写正文时：
1. 选项表逐行原样保留，包括被投中那一行末尾的 ♛ —— 不要删、不要改、不要合并成一行。
2. 骰子回执原样保留成 → 【1d10=7】这种形式，方括号和里面的数字都不能动。
3. 选项表和骰子留在正文中间，放在它所决定的那段情节之前。
4. 不要重投、不要改数值、不要加"（重投）""（其实失败了）"之类的话。
违反任意一条都算把这一回合写坏了。
```

> 技术上靠的是 `setExtensionPrompt` 的 **filter 参数**（1.14.0 支持，源码里 `if (hasFilter && !await prompt.filter())`）——
> 每次组装提示词时都会问一遍"这几条消息里有骰子吗"，没有就跳过。

### 如果你还想再加一层世界书

可以，但**别用默认设置**，否则基本没用。要让它咬得住，三条一起改：

1. **设为常驻**（蓝灯 / constant），别靠关键词 —— 否则条件不满足时它根本不存在
2. **位置选「按深度插入」`@D 0` 或 `@D 1`** —— 贴着生成点。放在角色定义区等于白写
3. 内容用**命令句 + 具体例子**，别写"建议""尽量"

内容可以直接抄上面那段 `【格式约束 —— 必须遵守】`。

## 子系统

### 属性 / 车卡 / 成长

```powershell
/anko attr sheet             # 默认八项属性各投一次 1d100
/anko attr set 话术 40
/anko attr add HP -3         # 相对修改
/anko attr clear
/anko growth 话术            # 成长检定
```

### 战斗轮

```
/anko combat begin 打手 12 10 45      # 敌人名 HP DEF [ATK]
/anko combat round                    # 结算一轮
/anko combat status
/anko combat end
```

- 单位：HP、ATK、DEF。**我方的这三个值存在属性表里**（`HP` / `ATK` / `DEF`，缺了就补默认 20/50/10），
  所以打起来面板上能直接看到掉血。
- 先攻：`1d100 + 修正`，开局投一次，大的先手（平手我方先手）。
- 命中：投 `1d100`，目标值 = `clamp(自身 ATK − 对方 DEF, 5, 95)`，骰值 ≤ 目标值即命中。
  - 骰值 1–5 **大成功** → 伤害 ×2
  - 骰值 96–100 **大失败** → 未命中，自己吃一次反伤
- 伤害：`1d10 + floor(ATK / 10)`
- **我方 HP ≤ 0 = 真的战死**：落成持久状态、HP 清零，并且**明确写进给 agent 的上下文简报**
  （「玩家角色已经战死……不要假装他还活着，也不要"奇迹般苏醒"来抹掉它」）。
  没有保底、没有怜悯 —— 骰子出什么就是什么。想反悔用 `/anko revive`。
- 敌方 HP ≤ 0 = 倒下（我方获胜）；敌方是死是活留给描写决定
- **硬上限 5 轮**：第 5 轮仍未分胜负 → **强制丝滑收场**，改投一次孔明式选项骰决定怎么结束
  （逃跑 / 敌方撤退 / 第三方打断 / 谈判停手 / 两败俱伤 / 大成功·大失败）。
  安科的战斗本来就不必分出胜负，「打不完就散场」比硬判输赢更有戏。

> 社区对"安科战斗系统"没有公认标准（有一堆征集帖但没结论），所以这套是自定的。命中公式和
> 5 轮上限都写在 `src/combat.js` 顶部，改起来是改常量。

## 设置项

| 设置 | 默认 | 说明 |
| --- | --- | --- |
| 发送前自动推演 | 关 | 打开后你一按发送，插件先跑一遍导演，用大纲**替换**你那条消息，再让主聊天演出 |
| 大纲直接发送（不给我改） | 关 | 关着就只是写进输入框，你能改 |
| 严格因果模式（强制一轮一骰） | 关 | 每轮只结算第一个骰子，表达式之后的文字丢弃（模型下一轮会重写）。代价是更慢更贵，换来严格因果 |
| 显示每颗骰子的原始点数 | 开 | 日志里带上原始点数，方便复核 |
| 用 prefill 续写 | 关 | 用 `prefill` 而不是内嵌续写。**Gemini 等 API 会报 400**（它们不允许请求以模型回合结尾），只有确认你的 API 支持时才开 |
| 轮数上限 | 12 | 导演循环最多几轮（1–50）。一个回合常要投 3–7 次骰子、一次骰子一轮，所以别设太小；最后一轮会自动禁止再开新骰子，保证收尾完整 |
| 选项骰命中行的标记符号 | ♛ | 插件投完选项骰后，在命中行末尾打这个符号。留空则不打标 |
| 锁死骰子格式 | **开** | 在正文 AI 的生成点前注入格式硬约束（见上）。只在有骰子内容时注入，平时不占 token |
| 结算正文 AI 写的骰子 | 关 | 打开后插件也结算**正文 AI 自己写**的骰子（含选项表命中标）。默认关：设计上骰子归导演，演员只负责叙述，不该再写新骰子 |
| 叙述人称 | **沿用前情** | 写大纲时的人称。**不设这条规则时，模型会照抄 prompt 范例里的人称，大纲的人称会一轮一个样**。可选：沿用前情 / 第一人称「我」/ 第二人称「你」/ 第三人称「名字」 |
| 导演走哪个预设 | **跟随当前设置** | 导演（大纲）那次请求走哪个**连接配置**。留空 = 用你此刻选中的设置；选某个配置 = 那次推演**带上它绑定的酒馆预设**，而且**不动你主聊天的设置** —— 于是能让导演用一个便宜快的模型去推演。拿不到配置时**自动退回当前设置**并提示 |
| 导演的 API（内置） | **关** | 打开后导演的请求**由插件自己发**（直连），完全不用酒馆的设置/预设/服务端。填接口形态（OpenAI 兼容 / Gemini）、地址（留空用官方默认）、API Key、模型名、温度、最大 token。**最大的坑是 CORS** —— 浏览器直连要求对方允许跨源，所以面板里有「测试连接」按钮先试一次。开了它，上面那个「走哪个预设」就不起作用了 |
| 导演能看到世界书 | **开** | 把当前**激活的**世界书整份塞进导演的上下文简报。**导演默认是看不到世界书的**（`generateRaw` 不跑主提示词组装，世界书正是在那一步注入的），所以它会编出跟设定冲突的东西。**代价**：一回合最多 12 轮，简报每轮都带 → 世界书每轮重复一遍，越大越贵。`/anko last` 会算出「世界书重复了多少字、占全部提示词的百分之几」，`/anko debug` 显示上次取了多少字 |
| 注入主提示词的状态文本 | 空 | 留空不注入。可用 `{{attrs}}` `{{combat}}` `{{story}}` 占位符 |

**提示词注入**默认是关的（骰点回执长在大纲里给读者看，不需要污染主聊天）。想让主聊天也知道
当前属性/战斗状态时，在注入框里写模板，例如：

```
【状态】{{attrs}}；{{combat}}
```

### 大纲体检工具

怀疑某次产出有问题时，不用肉眼数格子：

```powershell
node tools/verify-outline.mjs 大纲.txt
npm run verify -- 大纲.txt          # 同上
```

它**刻意不复用插件自己的逻辑**（用被验证的对象去验证它等于自证），而是重新朴素实现一遍，独立核：

- 每张选项表：区间是否从 1 连续铺满、末项是否「大成功/大失败」
- ♛ 是否**恰好一行**、是否落在包含骰值的那一行
- 两个骰子之间的**正文字数**（「收紧」的核心指标，默认上限 80，可用 `--prose-limit=N` 改）
- 结尾是不是**停在一个没解释的骰子上**（轮数被吃光的那种戛然而止）

在受限环境（比如沙箱）里 `node --test` 会因为 spawn 子进程被拦而报 `EPERM`，
可以直接跑每个测试文件（同进程执行，不 spawn）：

```powershell
npm run test:direct
```

## 已知限制

- **界面文案是中文**，只额外提供了 zh-tw。原因是本扩展的源语言就是中文，而酒馆没有 en 语言包，
  命令输出的长句翻译收益很低 —— 面板标签走 i18n，命令输出保持中文。
- **发送前自动推演会改你那条用户消息**（把输入换成大纲）。这是"替换玩家输入"在自动模式下的
  唯一落点：`GENERATION_AFTER_COMMANDS` 触发时消息已进 chat、但提示词还没组装。所以聊天记录里
  看到的就是大纲，而不是你最初那句话。
- 严格因果模式会丢弃表达式之后的文字，模型下一轮重写 —— 慢且贵，只在真的在意因果时开。
- **Gemini（Google AI Studio）有一个硬限制**：不接受「请求以模型回合结尾」。本插件默认的内嵌续写
  不受影响，但如果你在 Chat Completion 面板里手动配了 **Assistant Prefill**，普通发消息也会报
  同样的 400 —— 把那个设置清空即可。本插件的「用 prefill 续写」开关同理，别在 Gemini 上开。
- 骰点日志跟聊天存档走（`chatMetadata`）：**内存里留 500 条，落盘只留最近 100 条**（免得把聊天文件撑大）。
- 不走 `generate_interceptor`：导演循环用 `generateRaw`（不经过 `Generate()`，因此不触发扩展拦截器），
  这是为了避免和其他扩展的拦截器互相触发。
- `extension_prompt_types` / `extension_prompt_roles` 没有暴露在 `getContext()` 里，
  注入时按源码值在本地定义了 `PROMPT_POSITION`。
