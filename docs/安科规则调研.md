## 0. 先厘清：安科是什么、插件在其中的位置

- **安科**（日语 `あんこ`，`あんこスレ`）：起源于 AA 漫画的剧情推进形式。作者（**导游**）**自己预设若干选项**（通常 10 个），
  再用**随机点数**决定走哪一条。最初这种「不是安价」的做法被叫「安価ではない」，缩写成「あんこ」= 安科。
- **安价**（`安価`/`レスアンカー`）：用 `>>楼层号` 引用读者发言、**由读者决定走向**。缺点：读者天马行空的设定容易让剧情失控、
  作者要临场改写、原帖被安价回复淹没、看历史帖的人无法参与。
- 现在两者常**混用**：安价收集选项 → 骰子决定取舍。
- 关键的「官方」提法：为保证随机性与悬念，**选项表最后一项常安排「？？？？」或「大成功/大失败」**。

> 出处：[萌娘百科·安科](https://mzh.moegirl.org.cn/%E5%AE%89%E7%A7%91)、[萌娘百科·安价](https://mzh.moegirl.org.cn/%E5%AE%89%E4%BB%B7)

**插件的位置**：在酒馆里，**AI 扮演导游，插件扮演「骰子神」**。也就是：骰子由插件真随机生成、
结果由插件注入提示词强制 AI 采纳，而不是让 LLM 自己"编"一个点数。这一条决定了插件必须有确定性的骰子引擎 + 提示词注入。

> 术语：骰子常被敬称「骰子神」「骰子监督」，标记法 `[xDy]`（x 颗、y 面），`1D100` = 从 1~100 取 1 个值。
> 出处：[Reko Wiki·迪亞哥‧布蘭多似乎打算終結Grand Order的樣子](https://rekowiki.org/wiki/%E8%BF%AA%E4%BA%9E%E5%93%A5%E2%80%A7%E5%B8%83%E8%98%AD%E5%A4%9A%E4%BC%BC%E4%B9%8E%E6%89%93%E7%AE%97%E7%B5%82%E7%B5%90Grand_Order%E7%9A%84%E6%A8%A3%E5%AD%90)

## 1. 「孔明式」——国内主流规则（★ 最重要的一条）

萌百记载：**「目前国内原创的安科贴基本都使用了孔明式规则。」**
作者是《迪亚哥布兰度似乎在挑战 Grand Order 的样子》的作者「孔明」（`◆2sRGUbBO9j2n`）。

**规则内容**（两处来源互相印证，第二处是该作的真实骰点记录）：

1. **基础骰是 `1D10`，不是 1D100**。骰子决定 10 个选项中的哪一个。
2. **选项可以重复占多行 = 加权**。真实记录里第 3/4/5/7/8 项是同一句话，
   也就是那条走向被加权到 5/10 的概率。
3. **第 10 项固定是「大成功 / 大失败」**。投出 10 时，追加 `1D2` 决定是大成功还是大失败。
4. **大成功/大失败之后再追加一次 `1D10`**，用另一张表决定"大成功/大失败具体是什么效果"。
5. 于是可以**嵌套**：效果骰再出 10 → 再 `1D2` → 出现**双重大成功 / 双重大失败**（原作里出现过）。
6. `1D100` 在这套规则里用来做**数值积累**（伤害、好感度、食慾等），不是用来决定选项。

真实骰点记录（Reko Wiki 原文，可直接当验收样例）：

```
【1D10:9】
1.  只能自爆吧
2.  憑藉遷延的魔眼和呂布的武力勢均力敵
3.  戀愛方面果然是個糞雜魚鼻涕蟲跟蹤狂但戰鬥力很強喔蘇爾特君
4.  （同上，重复 = 加权）
5.  （同上，重复 = 加权）
6.  憑藉遷延的魔眼和呂布的武力勢均力敵
7.  （同上，重复 = 加权）
8.  （同上，重复 = 加权）
9.  呂布好強……
10. 【1D2:1】（1.大成功 2.大失敗）
```

同一页里还能看到 `【1D100:70】`（受到伤害）、`【1D100:92】`（食慾积累），以及叙述里的
「骰了个雙重大成功」「連骰兩次大成功」——证明加权、嵌套、连续大成功都是这套规则的日常。

> 出处：[萌娘百科用户页·安科规则](https://mzh.moegirl.org.cn/User:%E4%B8%89%E5%8E%9F%E8%89%B2%E5%BB%B6%E4%BB%81%E6%B3%B0/%E5%AE%89%E7%A7%91%E8%A7%84%E5%88%99)（该页把孔明式列为第一个、并注明是主流，但正文只有简述）、
> [Reko Wiki 同页](https://rekowiki.org/wiki/%E8%BF%AA%E4%BA%9E%E5%93%A5%E2%80%A7%E5%B8%83%E8%98%AD%E5%A4%9A%E4%BC%BC%E4%B9%8E%E6%89%93%E7%AE%97%E7%B5%82%E7%B5%90Grand_Order%E7%9A%84%E6%A8%A3%E5%AD%90)

**待你确认的点**：孔明式里 `1D10` 投出 1 只是普通选项（作者可以把最坏的放第 1 项），
**没有"1 = 大失败"这条**。如果你记得的规则不是这样，就是需要改的地方。

## 2. 判定体系：1D100 检定与大成功/大失败阈值（有权威枚举）

社区标准骰娘 **Dice!（Shiki）** 把 COC 的「房规」做成了 7 档，`setcoc` 可切换。
这是我能找到的**最明确、最可用的大成功/大失败阈值定义**：

| 房规 | 大成功 | 大失败 |
| --- | --- | --- |
| **0**（规则书） | 出 1 | 技能 <50 时出 96–100；≥50 时出 100 |
| **1** | <50 时出 1；≥50 时出 1–5 | <50 时出 96–100；≥50 时出 100 |
| **2** | 出 1–5 **且 ≤ 成功率** | 出 100，或出 96–99 **且 > 成功率** |
| **3** | 出 1–5 | 出 96–100 |
| **4** | 出 1–5 **且 ≤ 成功率/10** | <50 时出 ≥96+成功率/10；≥50 时出 100 |
| **5** | 出 1–2 **且 < 成功率/5** | <50 时出 96–100；≥50 时出 99–100 |
| **6** | 个位数 = 十位数 **且 ≤ 成功率** | 个位数 = 十位数 **且 > 成功率** |

> 房规 2 与 3 的区别：初始值为 1 的技能，在 2 下大成功率只有 1，在 3 下有 5。

检定指令本身（`.ra` / `.rc`）的能力：

- `.rc 困难智力 99`：`困难`/`极难`/`自动成功` 写在技能名**开头**视为关键词
- `.rc 体质*5`、`.rc 敏捷-10`：允许 `+ - * /`，但**运算顺序固定为 乘法 > 加减 > 除法**
- 修正后成功率必须落在 1–1000
- `.rc3#p 手枪`：轮数与奖惩骰各至多 9 个

> 出处：[Dice! 用户手册（GitHub 官方源）](https://raw.githubusercontent.com/Dice-Developer-Team/DiceV2Docs/master/User_Manual.md)

## 3. 骰点表达式语法（照这套实现，用户零学习成本）

Dice! 的表达式：`(次数#)(骰子个数)d(面数)(b奖励骰)(p惩罚骰)(k取最大)`

| 能力 | 示例 | 含义 |
| --- | --- | --- |
| 基础 | `.r 1d4+2 中型刀伤害` | 个数 1–100、面数 1–1000 |
| 默认骰 | `.r` | 面数默认 100，可 `.set` 改 |
| 乘法 | `.r 3d6X5 幸运` | `X` 与 `*` 都当乘号 |
| 多轮 | `.r 3#1d6 3发.22伤害` | 每次结果**分开发送**（也可 `1d10#`） |
| 取大 | `.r 3d6k2` | 取点数最大的 2 个骰子 |
| 奖励/惩罚骰 | `.rb2 瞄准后偷袭` / `.r3#p 手枪连射` | 奖惩骰固定为一个百面骰，不能与 h 以外字母共存 |
| 暗骰 | `.rh 心理学` | 结果**私聊发送**（玩家看不到） |
| 省略单骰 | `.rs 1D10+1D6+3 沙鹰伤害` | 直接给结果 |
| 骰池 | `.w` 直接给结果 / `.ww` 给出每颗骰子 | 固定 10 面骰，达到加骰参数则加骰，最后数 ≥8 的骰子数 |
| 先攻 | `.ri +5 boss`、`.ri2DK` | 生成先攻值并从大到小排序；`2DK` 是两次取大 |
| 轮盘骰 | `.game rou 20*5` | 把 X 面骰做成**轮盘**：每个点数必出且仅出 Y 次（防连续重复/保底） |

**轮盘骰**是很有意思的一条：它是「既随机又保证分布」的机制，直接对抗"骰子连续出同一个值导致剧情崩"，
`20*5` = 20 面、每点重复 5 次（总数 ≤100）。骰池**不**触发轮盘机制（会失去随机性）。

> 出处同上（Dice! 用户手册）

## 4. 安科专属：安价指令（`.ak`）

Dice! 内置了专门给安科用的指令族：

| 指令 | 作用 |
| --- | --- |
| `.ak#[标题]` / `.ak new [标题]` | 新建一轮分歧并设标题 |
| `.ak+[选项]` / `.ak add [选项]` | 添加选项，`|` 分隔可一次加多个 |
| `.ak-[序号]` / `.ak del [序号]` | 移除选项 |
| `.ak=` / `.ak get` | **均等随机抽取一个选项并结束本轮分歧** |
| `.ak show` / `.ak clr` | 查看 / 清除本轮 |

注意：这里的抽取是**均等**的——也就是说加权是孔明式（靠重复选项）而非权重字段。
**这是可以改的点**（加显式权重 vs 靠重复）。

> 出处：[Dice! 用户手册](https://raw.githubusercontent.com/Dice-Developer-Team/DiceV2Docs/master/User_Manual.md)

## 5. 导游风格：骰子掌控度（决定插件默认参数）

《论安科的写作》把安科按「导游对骰子的掌控程度」分三型，这直接决定插件的**默认加值/权重策略**：

| 类型 | 做法 | 代价 |
| --- | --- | --- |
| **权威型** | 加值要大；无论投出什么都有预案，保证大纲不被撕；往往**不接受安价** | 写法接近视觉小说，靠设计回应读者 |
| **中间派**（人数最多） | 有大纲，但掌控意愿不高，走一步看一步 | 面临"大纲粉碎"风险 |
| **混沌型** | 一切判定都交给骰子（比如全用 1D100） | 该文明确指出：随机游走会让叙事曲线像布朗运动一样偏离原点，**最终剧情崩坏、无法完结** |

同文还指出安科的爽点来源：「**这样的情节居然是能写的**」——骰子给剧情提供了表面上的、天然的合法性。
以及另一大类「**用随机性创造一整个世界**」（世界构筑型），这类需要**大量安价**，可以在多平台同时收集。

> 出处：[论安科的写作（B 站，原文发布于骨碌碌）](https://www.bilibili.com/opus/934757116146614288)

**这条对插件设计的直接含义**：必须提供一个「骰子权重/加值」旋钮，否则要么沦为混沌型（剧情崩），
要么导游要靠手改选项作弊。默认值建议偏权威型。

## 8. 待你决定（保留 / 修改）

具体选项见对话里的提问。汇总需要拍板的四类：

1. **骰点基础能力**：表达式、多轮、奖惩骰、暗骰、骰池、轮盘骰——要哪些。
2. **判定与大成功/大失败**：孔明式（1D10 第 10 项）还是 COC 房规（1D100 阈值），还是双轨。
3. **安科子系统**：安价、属性/车卡、成长、好感度、战斗、理智、事件表、牌堆。
4. **呈现与留痕**：侧栏状态板、骰点结果注入提示词、骰点日志/回放、暗骰、可验证性。
