# 安科导游 · 独立桌面版（Electron）

同一个仓库里两种形态：

| 形态 | 入口 | 说明 |
| --- | --- | --- |
| **酒馆扩展** | `index.js`（`manifest.json` 里声明） | 原来的用法，一行没改 ✓ |
| **独立 exe** | `main.js` + `renderer/index.html` | 双击就玩，不需要装酒馆 ✓ |

两者**共用同一个引擎**：`src/dice.js`、`src/rules.js`、`src/director.js`、`src/inline.js`、
`src/option-table.js`、`src/prompts.js`、`src/combat.js`、`src/state.js`、`src/api.js`
—— 这些模块只依赖**注入的** `rng` / `generate`，所以在酒馆里和 Electron 里跑的是同一套规则 ✓

## 跑起来（开发模式）

```powershell
cd D:\安科
npm install --ignore-scripts      # 受限环境里必须加 --ignore-scripts，见下面第 1 条
node node_modules\electron\install.js
npm run app:start
```

**最省事**：直接双击仓库根目录的 **`启动安科导游.cmd`** ✓（它会自动清掉 `ELECTRON_RUN_AS_NODE` ✓）

## 打包成 exe

双击 **`打包成exe.cmd`** ✓，或命令行：

```powershell
cd D:\安科
npm run app:dist     # 产物在 dist-app\安科导游-1.0.0.exe（单文件、免安装）
```

> ⚠️ **这两件事（启动/打包）都必须在你自己的普通终端里做** ✗ ——
> 在受限环境（沙箱）里 Node 的 `child_process.spawn` 被拦 ✓：
> Electron 起不来（要 spawn 渲染/GPU 子进程 ✓）、electron-builder 也起不来
> （`Cannot spawn app-builder.exe: spawn EPERM` ✓）。
> 这不是代码问题，是运行环境的边界 ✓。

## 版本号怎么看（别再被误导 ✗）

- `node_modules\electron\dist\version` 里写 **`32.3.3`** ✓ —— 这才是 Electron 版本 ✓
- `electron --version` 输出的 **`v20.18.1`** 是 **Electron 32 内置的 Node 版本** ✗ 不是 Electron 版本 ✓
- （我一度以为"镜像给错了包 / 装成了 v20"✗ —— **那个判断是错的** ✓，据此把主进程改成 CJS ✗。
  CJS 版**留着**是因为它对两个大版本都安全 ✓，但请知道它**不是**为了解决"v20"问题 ✓。）

## 设置填什么

| 项 | 说明 |
| --- | --- |
| **形态** | `openai` = 任何 OpenAI 兼容端点（OpenRouter、各种代理、自建网关 ✓）；`gemini` = Google 原生 |
| **Base URL** | 例：`https://openrouter.ai/api/v1`；自建网关就填你自己的 `/v1` |
| **API Key** | 存在 `%APPDATA%\安科导游\anko-settings.json` ✓ |
| **模型** | 必须填**端点认的名字**（端点会回 400 并列出它支持的名字 ✓ —— 那不是插件的错 ✓） |
| **温度 / 最大 token** | **留空 = 不传** ✓（推理型模型别乱设温度；最大 token 设太小会被思考吃光 → 正文为空 ✗） |

## 已知边界（诚实）

- **没有** 酒馆那套：世界书注入、面板命令、聊天元数据、多角色卡。前情目前是"最近 3 段导演输出"的纯文本 ✓
- 引擎的 343 个测试**照旧覆盖** exe 用的同一套 `src/` ✓（`npm run test:direct`）
- 打包后如果 `src/` 没被带进去 → 引擎会找不到 ✗。`build.files` 里已经写了 `src/**/*` ✓；
  `main.js` 放在**仓库根目录**就是为了 `import './src/...'` 在开发和打包两种情况下都成立 ✓

## 装依赖时踩的坑（2026-10-18 实测，别再踩一遍）

### 1. `npm install` 报 **EPERM**（写在 npm 缓存上）

```
npm error path C:\Users\PC\AppData\Local\npm-cache\_cacache\tmp\…
npm error FetchError: … EPERM: operation not permitted, open '…npm-cache…'
```

**根因**：npm 默认把缓存写到 `%LocalAppData%\npm-cache` ✓ —— 那**在工作区之外** ✗，
而受限环境只允许写工作区 ✓ → 所以不是"网络坏了"，是**缓存位置被拒** ✗。

**修法**（把缓存也搬进工作区）：

```powershell
$env:npm_config_cache = "D:\安科\.npm-cache"
npm install --no-audit --no-fund
```

### 2. `curl` / `Invoke-WebRequest` 一律报 SSL 失败，但**网络其实是通的**

```
curl: (35) schannel: AcquireCredentialsHandle failed: SEC_E_NO_CREDENTIALS (0x8009030E)
HTTP/1.1 200 Connection established     ← 代理/出网本身是好的
```

**根因**：`SEC_E_NO_CREDENTIALS` 是 **Windows 的 TLS 栈（schannel）** 拿不到客户端凭据 ✗ ——
在受限进程里很常见 ✓。**和墙、证书、DNS 都无关** ✗（连 `baidu.com` 也一样失败 ✓）。

**判断方法**：别用 `curl`/`Invoke-WebRequest` 测网络 ✗ —— 它们走 schannel ✓；
**用 `node -e` 或 `npm`**（自带 OpenSSL + 自己的 CA ✓）✓ —— 实测同一条网络下 npm 一路 200 ✓。

### 3. Electron 二进制从 GitHub 下太慢/下不动

设镜像（electron 本体 + builder 的二进制都设 ✓）：

```powershell
$env:ELECTRON_MIRROR = "https://npmmirror.com/mirrors/electron/"
$env:ELECTRON_BUILDER_BINARIES_MIRROR = "https://npmmirror.com/mirrors/electron-builder-binaries/"
```

### 4. 跨模块 import 前先验证"导出真的存在"

`main.js` 第一版写了 `import { clampBudget } from './src/prompts.js'` ✗ ——
而 `clampBudget` 在 `prompts.js` 里是**模块私有**的、没导出 ✓ →
**语法检查查不出来**（`node --check` 不解析 import ✓），**要到运行时才 TypeError** ✗。

**规矩**：新写的入口（`main.js` 这种）里每个 import，都要有一条"导出存在性"检查 ✓
（动态 `import()` 一下、断言 `typeof` ✓，沙箱里也能跑 ✓）。本次就是靠它当场抓到的 ✓。

### 5. ⚠️ 最坑的一条：`ELECTRON_RUN_AS_NODE=1` 会让 Electron **伪装成纯 Node**

**症状**（全是同一个原因，很容易误判成四个不同的 bug ✗）：

```
TypeError: Cannot read properties of undefined (reading 'exports')
    at cjsPreparseModuleExports (node:internal/modules/esm/translators:379)
  Node.js v20.18.1                       ← 报的是 Node 的版本，不是 Electron 的

TypeError: Cannot read properties of undefined (reading 'whenReady')
    at Object.<anonymous> (main.cjs:96)  ← require('electron') 拿到的不是 API

$ electron --version
v20.18.1                                 ← 也变成 Node 的版本了 ✗

# 探针（决定性）：
$ electron probe.cjs
[A] typeof require('electron') = string  ← 返回了"路径字符串"（npm 包的导出），而不是内置 API
[A] typeof e.app = undefined
```

**根因**：进程环境里有 **`ELECTRON_RUN_AS_NODE=1`** ✓ —— Electron 会**以纯 Node 身份**运行你的脚本 ✗，
于是：没有 `app` / `BrowserWindow` ✓、`require('electron')` 走 npm 包（导出 exe 路径 ✓）、
`--version` 报 Node 版本 ✓。**和代码、版本、ESM 都无关** ✗。

**查与清**（PowerShell）：

```powershell
[Environment]::GetEnvironmentVariable('ELECTRON_RUN_AS_NODE')   # 看有没有
Remove-Item Env:\ELECTRON_RUN_AS_NODE -ErrorAction SilentlyContinue
```

**规矩**：Electron 起不来、报的又是"没头没脑的 undefined"时，**先查这个变量** ✓，
再去怀疑版本/ESM/打包 ✗ —— 本次就是在这上面绕了好几轮（v20 vs v32、ESM vs CJS）✗。

### 6. `.cmd` / `.bat` 里**绝不能写中文**，也不能带 BOM

**症状**（用户双击后满屏）：

```
'?rem' 不是内部或外部命令
'S_NODE' 不是内部或外部命令
'姩澶辫触锛岄€€鍑虹爜' 不是内部或外部命令     ← 中文注释变成乱码，又被当成命令
'l.js' / '..' / 'E' / '1.' / '2.' 不是内部或外部命令
```

**根因**：
- 文件带 **UTF-8 BOM** ✗ → `cmd.exe` 把 BOM 当成第一个命令的一部分 → `'?rem'`
- 文件里有**中文** ✗ → `cmd.exe` 按 **OEM 代码页（简中是 GBK）** 读 ✗ →
  中文注释变乱码 ✓，乱码里一旦含 `&` `|` `(` `)` 等字符，**整行会被撕成几条命令** ✗

**规矩**：
1. `.cmd` 一律**纯 ASCII** ✓（注释也用英文 ✓）
2. **不要 BOM** ✓
3. 验证方法：读字节，断言每个字节 ≤ 127、前 3 字节不是 `EF BB BF` ✓
   （本次就是这样确认干净的：`非ASCII字节=0  BOM=False` ✓）
