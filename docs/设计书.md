## 1. 一句话定位

**插件在酒馆里内置一个「导演 agent」**：它替玩家把安科的一个回合推演完 —— 多轮写大纲、
在需要分歧的地方列出要骰的点、由插件真随机投骰、把骰点结果吃进大纲，最后**用写好的大纲替换玩家的输入框**，
交给主聊天去演出。

分工是死的：

| 角色 | 是谁 | 职责 |
| --- | --- | --- |
| 导游 / GM | 插件里的 agent | 写大纲、决定"哪里需要骰"、解释骰点、产出玩家发言 |
| 骰子神 | 插件本体 | **真随机**投骰，agent 无权改动结果 |
| 演员 | 主聊天（角色卡 + 你原来的提示词） | 按大纲演出正文 |

**关键红线：骰子值只能由插件生成，agent 不能自己编点数。** 这是整个插件存在的理由。

---

## 2. 目标 / 非目标

### 目标

1. 玩家写一句话（或者只写个方向），插件产出一份**可执行的回合大纲**，并把它放进输入框。
2. 大纲里的每个分歧点都是**真骰出来的**，且**可复核**（附录记了表达式、结果、依据）。
3. agent 有**多轮**能力：先草拟 → 发现需要骰 → 拿到骰点 → 继续写，而不是一次成文。
4. 规则实现贴合国内通行做法（孔明式 + COC 房规3），玩家不用学新东西。

### 非目标（这一期明确不做）

- ❌ 不做多轮掷骰**记法** `#`、奖励/惩罚骰 `b/p`、暗骰 `h`、骰池 `w/ww`、轮盘骰（你的选择）
  （注意：这里的 `#` 是骰子表达式语法，和 agent 的"多轮循环"是两回事）
- ❌ 不做好感度系统、理智/疯狂、牌堆与抽卡（你的选择）
- ❌ 不做服务端插件（插件要能进官方内容库，且必须纯前端可跑）
- ❌ 不替主聊天写正文 —— 大纲只到"这一回合发生了什么、玩家说了什么"

## 3. 核心流程

```
玩家在输入框写：「我想去酒吧打听消息」
        │
        ▼
[1] 玩家点「推演本回合」按钮（或 /anko 斜杠命令）
        │
        ▼
[2] 插件收集上下文：角色卡摘要 + 最近 N 条聊天 + 世界书 + 角色属性表 + 当前剧情线
        │
        ▼
[3] ┌─────────── 导演 agent 多轮循环（上限 R 轮）───────────┐
    │                                                       │
    │  a. 调用 agent（generateRaw，独立上下文）              │
    │  b. 扫输出里的**内联骰子表达式**（如 1d3 / 1d100 / 1d10）│
    │  c. 没有表达式 → 本轮即定稿，跳出                        │
    │  d. 在第一个表达式处**截断**，投骰，把 `1d3` 原地替换成   │
    │     `【1d3=2】`，再把定稿作为 prefill 喂回去续写         │
    │  e. 回 a                                                │
    └───────────────────────────────────────────────────────┘
        │
        ▼
[4] 产出：回合大纲（含骰点附录）
        │
        ▼
[5] 用户确认（可编辑）→ 写入输入框，替换玩家原来的那句话
        │
        ▼
[6] 玩家按发送 → 主聊天生成正文
        │
        ▼
[7] 拦截器在每个生成请求前，把「当前属性/状态/战斗轮」注入提示词
```

第 3 步是全部难点所在。第 5 步的"替换"默认是**写入输入框等你改**，不是直接发出去（见 D2）。

### 3.1 机制：内联骰子 + 截断续写

骰子是**直接写在正文里的**，不是单独一行的请求：

```
我把行李寄在旅店，第二天清晨动身去码头。水路走了1d3天。
                                            └── AI 写到这里停住
```

插件在这一处接管：投骰 → 把结果**原地替换** → 把定稿喂回去让 AI 接着写：

```
我把行李寄在旅店，第二天清晨动身去码头。水路走了【1d3=2】天。
                                            └── 从这里继续往下写
```

**严格说不是模型自己停**：模型其实还在往下写，是插件在第一个骰子表达式处
**截断、丢弃后面的内容**，投完骰再把定稿当作续写起点喂回去。
效果上等价于"AI 停住等骰子"，但这么做**不依赖模型的自觉** —— 它不听话也不会出错，只是浪费一点 token。

### 3.2 完整例子（6 轮）

```
玩家输入：我去码头打听失踪商队的事        属性：话术 40
```

**第 1 轮** — AI 写到 `1d3` 就停（后面即使继续写了也被丢弃）

```
我把行李寄在旅店，第二天清晨动身去码头。水路走了1d3天⌷
```
> 插件投 `1d3` → **2** → 定稿：`…水路走了【1d3=2】天。`

**第 2 轮** — 从定稿续写，AI 自己给出选项表

```
…【1d3=2】天。靠岸时我发现告示牌上贴着悬赏——画的正是商队那个向导。

先去哪边打听 —— 选项骰十项：
  1-3 酒馆    4-6 货栈    7-9 码头管事    10 【1D2】大成功/大失败
→ 1d10⌷
```
> 插件投 `1d10` → **7** → 定稿：`→ 【1d10=7】`
>
> ⚠️ 表头写「选项骰十项」而**不写 `（1d10）`**。写了的话那个 `1d10` 会被扫描器
> 当成一个永远待投的骰点（这是写测试时踩出来的真问题，见 §4.3 铁律 4）。

**第 3 轮** — AI 自己把 7 解释成"码头管事"，然后发起属性检定

```
…→ 【1d10=7】，落在 7-9：我找了码头管事。

管事是个精瘦老头，听完来意只眯起眼：「商队？三天前就走了。」他在撒谎。
我试探他 → 1d100【话术40】⌷
```
> 插件投 `1d100` → **68**；按房规 3 判定：68 > 40 → **失败**
> 定稿：`→ 【1d100=68 / 话术40 → 失败】` —— **成败结论由插件给出，不让 AI 自己判**
>
> 技能与成功率写在表达式**后面的 `【】` 里**，整块一起被替换，所以不会留下重复的技能名。

**第 4 轮** — 因为失败了，AI 写"事情闹大"的分支表

```
…【1d100=68 / 话术40 → 失败】。管事听出我在套话，手往柜台下面摸。

这事会闹成什么样 —— 选项骰十项：
  1-4 把我轰出去   5-7 叫来打手   8-9 叫打手并惊动幕后   10 【1D2】大成功/大失败
→ 1d10⌷
```
> 插件投 `1d10` → **10** → 命中孔明式：**自动连投** `1d2` → **2（大失败）**
> 定稿：`→ 【1d10=10 → 1d2=2（大失败）】`

**第 5 轮** — AI 看到大失败，自己补一张大失败效果表

```
…→ 【1d10=10 → 1d2=2（大失败）】

大失败效果表 —— 选项骰十项：
  1-3 挨一顿打   4-6 身份暴露、消息走漏   7-9 挨打且丢了钱袋   10 【1D2】双重大成功/大失败
→ 1d10⌷
```
> 插件投 `1d10` → **4** → 定稿：`→ 【1d10=4】`

**第 6 轮** — AI 收尾，不再出现骰子表达式 → **本轮即定稿，跳出**

最终产物（替换输入框，你还能改）：

```markdown
▸ 回合：码头打听

行李寄在旅店，第二天清晨动身去码头。水路走了【1d3=2】天。
靠岸时我发现告示牌上贴着悬赏——画的正是商队那个向导。

先去哪边打听 —— 选项骰十项：1-3 酒馆 / 4-6 货栈 / 7-9 码头管事 / 10 大成功·大失败
→ 【1d10=7】落在 7-9：我找了码头管事。

管事是个精瘦老头，听完来意只眯起眼：「商队？三天前就走了。」他在撒谎。
我试探他 → 【1d100=68 / 话术40 → 失败】

管事听出我在套话，手往柜台下面摸。
→ 【1d10=10 → 1d2=2（大失败）】
大失败效果 → 【1d10=4】→ 4-6 区间：身份暴露，消息走漏。

我走出管事房时，感觉背后有两道视线。
```

骰点回执**长在大纲正文里**（读者看得到投了什么，这是安科的乐趣），
而不是注入主提示词 —— 对应你没勾"结果注入提示词"，见 D8。

## 4. 导演 agent 设计

### 4.1 为什么用 `generateRaw`

| 候选 | 判断 |
| --- | --- |
| `generateRaw({ prompt, systemPrompt })` | ✅ **选它**。完全独立上下文，且**不经过** `Generate()`，因此**不会触发扩展拦截器** → 天然没有自我递归风险（这点我已经在源码里验证过） |
| `generateQuietPrompt()` | ❌ 走 `Generate('quiet')`，**会再次触发所有扩展的拦截器**（包括我们自己），是递归重灾区 |
| `registerFunctionTool()` | ⚠️ 可选增强。但 `canPerformToolCalls` 对 `quiet`/`impersonate`/`continue` 返回 false，且 `generateRaw` 不走 ToolManager 循环，所以工具调用在 agent 循环里得自己实现 —— 不如直接自定协议（见 D4） |

**结论**：agent 循环用 `generateRaw`，自己组装上下文。可控、无递归、不污染主聊天。

### 4.2 循环结构（截断续写 + 一轮多骰）

```
function runDirector(userInput):
    settled = ''                      # 已定稿、已锁定的大纲文本
    日志 = []

    for round in 1..R:                                 # R 默认 12，见 D9
        raw = generateRaw({
            systemPrompt: DIRECTOR_PROMPT,
            prompt:       上下文简报 + userInput,
            prefill:      settled,                     # 已定稿部分作为续写起点
        })

        hits = allUnresolvedDice(raw)                  # 左到右收集，跳过 【】 内已解析的
        if hits is empty:
            settled += raw
            return outline(settled, 日志)              # 没有骰子 = 本轮定稿、跳出

        # 本轮把所有骰子一次性结算（左→右），文本全部保留
        cursor = 0
        for hit in hits:
            settled += raw[cursor .. hit.start]
            roll = diceEngine.roll(hit.expr, hit.context)   # 真随机，AI 无权干涉
            settled += format(hit.expr, roll)               # 原地替换成【1d3=2】，写入即锁定
            日志.push(roll)
            cursor = hit.end

            # 孔明式：选项骰投出 10 → 立刻自动连投 1d2
            if hit.isOptionRoll and roll.value == 10:
                sub = diceEngine.roll('1d2')
                settled += ` → 1d2=${sub.value}（${sub.value == 1 ? '大成功' : '大失败'}）`
                日志.push(sub)

        settled += raw[cursor ..]                      # 最后一个表达式之后的文字也保留

    return outline(settled, 日志)                      # 到上限就用现有定稿
```

**五条硬约束**：

1. **一轮多骰**（你的选择）：一次输出里的所有表达式**左到右全部结算**，文本全部保留。
2. **已定稿即锁定**（"只要不改"）：`【1d3=2】` 一旦写入就**不再让模型改写** —— 否则它可以悄悄"重骰"。
   锁定是插件强制的：模型后续输出里若出现已投过的表达式或 `【】` 内容，一律以插件记录为准。
3. **因果靠 prompt 约束**（⚠️ 多骰的代价，你必须知道这条）：
   多骰意味着"后面的文字是在**不知道**前面骰值的情况下写的"。
   ```
   他投了1d100，结果失败，于是他1d10            ← 写 1d10 时它还不知道 1d100 是成功还是失败
   ```
   所以 prompt 里必须教：**一旦后续叙述要依赖某个骰值，那个表达式就单独写、写完停笔**（退化成上一版的一轮一骰）；
   只有**彼此独立、骰值只填在替换位**的场合（批量生成 NPC、列举数值）才一次写多个。
   插件无法自动判断"依赖与否"，因此另给一个 **「严格因果模式」开关**强制一轮一骰兜底。
4. **上限可中断**：整个循环包在 `loader.show({ message, onStop })` 里，玩家能随时掐掉。
5. **不做无进展的死循环**：若连续 2 轮已定稿长度都没增加，直接跳出。

### 4.3 内联骰子的书写规范（prompt 里要教死这四条）

| 场合 | AI 怎么写 | 插件投完替换成 |
| --- | --- | --- |
| **纯数值** | `水路走了1d3天` | `水路走了【1d3=2】天` |
| **选项 / 查表** | **表写在表达式前面**，表头用**文字**描述（「选项骰十项」），最后一行 `→ 1d10` | `→ 【1d10=7】`，由 AI 自己解释落在哪个区间 |
| **属性检定** | `1d100【话术40】` —— 技能与成功率写在表达式**紧后面的 `【】` 里** | `【1d100=68 / 话术40 → 失败】`，整块替换、不留残渣，**成败由插件按房规 3 算** |
| **选项骰注解** | `1d10【选项】` —— 告诉插件"这是选项骰，投满就触发大成功/大失败" | `【1d10=10 → 1d2=2（大失败）】`，然后停下等 AI 给效果表 |
| **大成功/大失败** | 表的第 10 项固定写 `10 【1D2】大成功/大失败` | 投出 10 时插件**自动连投** `1d2`；若是大失败，AI 再补效果表并请求下一个 `1d10` |

**注解协议**（已实现于 `src/inline.js` 的 `parseAnnotation` / `findDiceUnits`）：
表达式后面紧跟一对方括号就是注解，**注解和表达式整块一起被替换**。
- `【话术40】` / `【图书馆使用 65】` / `【检定 话术 40】` → 检定（只认 1d100）
- `【选项】` / `【选项骰】` → 孔明式选项骰（只认 1dN，N≥2）
- 注解用错骰子时**不抛错**，降级成普通投骰 + 把原因喂回给模型让它改

四条铁律（后两条是写测试时踩出来的真问题）：

1. 必须是**可解析的字面量**（`1d3`、`2d6+3`、`1d100`）—— 不许写成"一到三天""看运气""随机决定"。
2. 已经投过、带 `【】` 的结果**锁定**，AI 不许回头改。
3. **骰值影响后文时，那个表达式要单独写、写完停笔**；彼此独立的骰子（批量生成 NPC、填数值）可以一次写多个 ——
   插件会按顺序全部结算。判错的代价只是那一处因果不自然，不会出错。
4. **一个表达式只写一次**。两条实测出来的坑：
   - 表头写成 `（1d10）：` → 那个 `1d10` 会被当成**永远待投**的骰点（它是标签不是请求，但扫描器分不出来）。
     所以表头写「选项骰十项」这种**文字**，表达式只出现在 `→ 1d10` 那一行。
   - 检定写成 `（1d100，话术 40）→ 1d100` → 两个表达式会被**各投一次**。
     所以用 `1d100【话术40】` 这个复合写法，整块一起替换。

> 为什么不加壳（比如写成 `{{1d3}}`）：你的例子里是裸写，而且安科原文本来就是裸写 `1d3`。
> 裸写靠正则 `\d+[dD]\d+` 识别，正则会跳过 `【】` 内的已解析结果。要不要加壳见 D15。

### 4.4 agent 的 system prompt 骨架

必须在 prompt 里钉死的几条（否则模型必然乱来）：

- 你是**导演**，不是骰子。需要随机性时，**把骰子表达式直接写进正文**（如 `走了1d3天`），**写完立刻停笔** ——
  插件会在那一处接管、投骰、把结果原地填回去，然后叫你续写。
- **禁止自己编造骰点数值**；**禁止改写已经出现 `【】` 的定稿**（那是已经锁定的事实）。
- 一次可以写多个表达式，**但只有在它们互相独立、骰值只填在替换位时**（如批量生成 NPC、列举数值）；
  一旦后续叙述要依赖某个骰值，就**只写那一个、写完停笔**，等结果回来再续写。
- 表达式只能出现**支持的文法**（见 §5.1），否则插件会拒骰并要求你改正。
- 什么时候该骰（这条要写死，否则模型要么不骰要么乱骰）：
  - 玩家行动**结果不确定**且**失败有意义** → 属性检定 `1d100`，同一处注明技能名与成功率
  - 出现**多个可行走向**且作者不想独断 → 选项骰 `1d10`，表写在前、第 10 项固定写大成功/大失败
  - **纯描写/无风险动作** → 不骰
- 拿到 `【1d100=68 / 话术40 → 失败】` 这样的回执后，**必须按结果往下写** ——
  不许"我本想说成功但……"，也不许再投一次同样的骰子试图翻盘。

### 4.5 选项表的命中标注（插件做的，不是 AI 做的）

选项骰投完之后，读者最想知道"投中了哪一行"。这件事**不能交给 AI** —— 它经常忘、也经常标错。
按"谁投的骰子谁负责标结果"的原则，插件自己来：`src/option-table.js`。

```
先去哪边打听 —— 选项骰十项：
1-3 酒馆
4-6 货栈
7-9 码头管事 ♛        ← 插件打的
10 【1D2】大成功/大失败
→ 【1d10=7】            ← 骰子本身保留
```

实现要点：

1. **只对带 `【选项】` 注解的骰子打标** —— 普通 `1d10`（伤害之类）绝不会去标任何表
2. 从结果位置**往回**逐行读：先跳过 `→` 这种请求行，再收集"行首是号数或区间"的行，碰到别的行就收手
3. **两道防误伤闸**（第二道是写测试时踩出来的）：
   - 行首号数必须**从 1 连续铺满** —— 有洞、有重叠、不从 1 开始都拒绝
   - 还要上面那行**像表头**（含「选项/骰/表/项」或以冒号结尾的短行），或者行数 ≥5，或者表就在正文开头。
     因为正文里出现 `1 走吧 / 2 留下` 这种编号列表很常见，光靠"编号连续"分不出来
4. **认不出来就什么都不做** —— 宁可不标，也不改坏正文
5. 多处打标用**精确下标 + 从后往前**，避免插入字符影响后面的位置
6. 幂等：已经标过的不叠第二个；符号可配（默认 `♛`），留空即关闭

## 5. 骰子引擎规范（按你的裁剪）

### 5.1 文法（只做这些）

```
表达式   := [加值项] { ("+" | "-") 骰项或常数 }
骰项     := 数量 "d" 面数 [ "k" 取大数 ]
常数     := 整数
乘号     := "X" | "*"          # 3d6*5
```

| 支持 | 示例 | 说明 |
| --- | --- | --- |
| 基础 | `1d100`、`1d10`、`3d6+2` | 数量 1–100、面数 1–1000（越界直接报错，不静默截断） |
| 加值/减值 | `1d100-10`、`1d6+1d4+3` | |
| 乘法 | `3d6X5`、`3d6*5` | 结果整体乘 |
| 取大 | `3d6k2` | 取最大的 2 颗求和 |
| 默认骰 | 不写表达式时 `1d100` | |

**不做**（你的选择）：`#` 多轮、`b/p` 奖惩骰、`h` 暗骰、`w/ww` 骰池、轮盘骰。

### 5.2 双轨判定

**轨道 A — 属性检定（COC 房规 3）**

| 骰值 | 判定 |
| --- | --- |
| 1–5 | **大成功** |
| 96–100 | **大失败** |
| ≤ 成功率 | 成功 |
| > 成功率 | 失败 |

大成功/大失败**不需要**再骰效果表 —— 由 agent 依据剧情写；但如果这一判定本身是选项骰的触发条件，就走轨道 B。

**轨道 B — 选项骰（孔明式）**

```
投 1D10
├─ 1..9  → 直接采用第 N 项（重复选项 = 加权，行数即权重）
└─ 10    → 投 1D2 决定大成功(1) / 大失败(2)
           └─ 再投 1D10，查「大成功效果表 / 大失败效果表」
               └─ 若效果骰又是 10 → 再 1D2 → 双重大成功/大失败（最多嵌套 2 层，超出记为"传奇"）
```

选项表由 agent 生成，**必须**满足：10 项、第 10 项固定是 `【1D2】大成功/大失败`、允许重复行做加权。

### 5.3 随机性与可复核

- 随机源：`crypto.getRandomValues()`（不是 `Math.random()`）—— 骰子是这个插件的立身之本，不该用弱随机。
- 每次投骰记录：`{ 时间, 表达式, 明细（每颗骰子的原始值）, 结果, 理由, 判定结论, 轮次 }`。
- 日志落在 `chatMetadata`（跟聊天存档走）。虽然你没勾"骰点可验证"，但记录原始明细几乎零成本，
  且**玩家要求复核时你能立刻答出来**（D12）。

## 6. 规则子系统（本期要做的四个）

### 6.1 角色属性 / 车卡 / 成长

- **属性表**：`{ 名称: 数值 }`，另存 `上限`、`标签`（如 `力量/敏捷/智力/幸运`）。
- **车卡**：`/anko 车卡` 让 agent 按 COC 风格生成，或玩家手填；也支持从当前角色卡读描述反推。
- **存放**：跟聊天绑定的放 `chatMetadata`；想让属性**跟着角色卡走、可导出分享**的用
  `writeExtensionField(characterId, 'anko_attrs', ...)`。⚠️ `characterId` 是数组下标、群聊里为 `undefined`
  （这条是我从官方文档确认的坑），所以群聊场景必须有降级路径。
- **成长检定**：对已用过的技能投 `1d100`，`> 当前值` 或 `≥ 95` 则成长（COC 式）。

### 6.2 战斗轮（已实现）

社区有一堆"战斗系统征集/讨论"帖但**没有公认标准**，所以这套是自定的。
**下面就是 `src/combat.js` 里真正跑的规则**（改起来是改常量）：

```
单位：{ name, hp, maxHp, atk, def, initMod }
  我方这三个值存在属性表里（HP / ATK / DEF），缺了就补默认 20 / 50 / 10
  所以打起来面板上能直接看到掉血

先攻：1d100 + initMod，从大到小（开局投一次）；平手我方先手
命中：攻方投 1d100，目标值 = clamp(自身 ATK − 对方 DEF, 5, 95)，骰值 ≤ 目标值即命中
  · 骰值 1–5    大成功 → 伤害 ×2
  · 骰值 96–100 大失败 → 未命中，自己吃一次反伤（= ceil(伤害 / 2)）
伤害：1d10 + floor(ATK / 10)
我方 HP ≤ 0 → **真的战死**：result = 'selfDead'，上层落成持久死亡状态并写进给 agent 的简报
敌方 HP ≤ 0 → 倒下（result = 'selfWin'）；敌方是死是活留给描写决定
随机源是 crypto，**没有保底、没有怜悯**
```

> 与初稿的两处差别：命中不再是"1d100 vs DEF"这种含糊说法，而是明确的
> `clamp(ATK − DEF, 5, 95)`（夹取是为了别出现必中/必不中）；伤害公式也定死了。
>
> ⚠️ 初稿写的「HP ≤ 0 → 战斗结束（**不判定死亡**，描写交给 agent）」已被推翻 ——
> 那是个含糊的免责，插件自己都不承认人死了，AI 更会糊过去。现在**我方死了就是真死**。

**硬上限 5 轮 —— 第 5 轮仍未分出结果，强制「丝滑收场」**（你的定案，已实现）：

改投一次**孔明式选项骰（十项）**，用这张表决定战斗怎么结束：

| 1d10 | 收场方式 |
| --- | --- |
| 1–2 | 我方抓住空隙脱身，战斗就此打住 |
| 3–4 | 敌方主动撤退，留下一句场面话 |
| 5–6 | 第三方插进来打断了这场架 |
| 7–8 | 双方打到一半开始谈条件，暂时停手 |
| 9 | 两败俱伤，各自退开，谁也占不到便宜 |
| 10 | 【1D2】大成功 / 大失败 |

- **不追求分出胜负** —— 安科的战斗本来就能以逃跑、中断收场，留一个 `10` 兜底更有戏
- 大成功 → 「战局被彻底逆转，我方占尽上风」；大失败 → 「战斗以最糟的方式收场，局势失控」
- 丝滑收场也走同一套内联骰子写法，所以玩家照样看得到投了什么

### 6.3 随机表 / 事件表

- 表格结构：`{ 名称, 骰式: '1d100', 条目: [{ 区间/权重, 结果 }], 可替换变量 }`
- 内置几张常用的（随机事件、随机名字、随机地点、天气、遭遇），玩家可自建、可导入导出 JSON。
- 取值支持**区间**（`1-5`）和**权重**两种写法，避免只支持均分。
- agent 可以请求查表：`【ROLL: table:随机事件】`。

### 6.4 安价

在酒馆单机环境下，"读者"是谁需要定义（**D7**）。我按可插拔设计，三种来源：

| 来源 | 流程 |
| --- | --- |
| **AI 生成**（默认） | agent 直接给 10 项选项表 → 孔明式骰选 |
| **玩家手输** | 插件弹输入框，玩家填选项（一行一个）→ 骰选 |
| **预设表** | 从 §6.3 的随机表里取 |

投骰**均等**（没选轮盘骰/权重字段，所以加权靠重复行）；`/anko 安价` 手动触发一轮。

## 7. 与酒馆的集成点

全部只用 `SillyTavern.getContext()`，不 import 内部模块（见规范文档 §3）。

| 需要 | 用什么 |
| --- | --- |
| agent 循环里生成 | `generateRaw({ systemPrompt, prompt })` |
| **续写（关键，已改为内嵌）** | 默认把已定稿文本放进**用户消息**里（`buildDirectorPrompt` 的 `settled`），让模型接着写。原先用 `generateRaw({ prefill })` —— 它会被 `createRawPrompt` 作为**一条 assistant 消息追加在末尾**，但 **Gemini 拒绝「请求以模型回合结尾」**（HTTP 400 `Requests ending with a model turn are not supported`），所以 prefill 降级成可选开关（`usePrefill`，默认关）。内嵌方式前缀缓存照样有效（固定部分在前、已定稿在末尾），并靠 `stripEcho()` 处理模型重抄 |
| **发送前自动推演** | 挂 **`MESSAGE_SENT`**（`(insertAt)` 消息下标）—— 用户消息进 `chat` 之后、提示词组装之前。⚠️ 监听器**必须把 Promise 返回给事件系统**（不能 `void` 掉），酒馆会 await 监听器返回值，否则会在推演完成前就开始组装提示词 |
| 把大纲写回用户消息 | 直接改 `chat[最后一条].mes`，再 `updateMessageBlock(index, mes)` 重绘。源码签名：`updateMessageBlock(messageId, message, { rerenderMessage = true })` |
| 大纲写进输入框 | `$('#send_textarea').val(text).trigger('input')` |
| 直接发送（可选） | `$('#send_but').trigger('click')` —— 比 STscript `/send` 稳，不会被斜杠命令解析吃掉 |
| 主聊天注入状态 | `setExtensionPrompt(key, text, 1 /*IN_CHAT*/, depth, false, role)` |
| 写进输入框 | `$('#send_textarea').val(outline).trigger('input')` |
| 直接发送（可选） | `executeSlashCommandsWithOptions('/send …')` |
| 长任务可中断 | `loader.show({ message, stopTooltip, onStop })` → `handle.hide()` |
| 写大纲前的确认 | `Popup.show.confirm(...)` / `new Popup(html, POPUP_TYPE.TEXT, ...)` |
| 面板 | `renderExtensionTemplateAsync` + `#extensions_settings2` |
| 斜杠命令 | `SlashCommandParser.addCommandObject(SlashCommand.fromProps(...))` |
| 每聊天状态 | `chatMetadata` + `saveMetadataDebounced()`（**切聊天前要 `saveMetadata()` 立即存**，防抖版会放弃保存，源码级坑） |
| 全局设置 | `extensionSettings[MODULE_NAME]` + `saveSettingsDebounced()` |
| 角色卡属性 | `writeExtensionField()` / `constants.unset` |
| token 预算 | `getTokenCountAsync()` |
| 排障 | `registerDebugFunction('anko_dump', ...)` |
| 清理 | 在 `onDisable` 里摘监听、清注入、关面板 |

**不碰**：`messageFormatter.addHook()`（官方仍标 staging）、`doExtrasFetch`（已废弃）。

## 10. 风险与对策

| 风险 | 对策 |
| --- | --- |
| agent 自我递归（在循环里又触发拦截器） | 用 `generateRaw`，它不经过 `Generate()`，源码已验证不触发拦截器 |
| agent 自己编骰点 | 协议里禁止 + 正则扫描输出，发现凭空出现 `1D100 = 88` 就丢弃该轮并重来 |
| 多轮烧 token / 卡死 | 轮数上限 + 连续无进展跳出 + `loader` 可中断 + 轮次预算展示 |
| **多骰的因果倒置**：后文是在不知道前一个骰值的情况下写的 | prompt 里教"依赖后文就单独写、写完停笔"；给「严格因果模式」开关强制一轮一骰；锁定规则保证骰值本身不会被改 |
| **每轮重发已定稿文本 → token 随轮数近乎平方级增长** | ① 轮数上限（默认 12）；② 依赖 API 的**前缀缓存**（DeepSeek / Anthropic / OpenAI 都有，重复前缀命中后极便宜）；③ 轮数多时把已定稿部分摘要压缩 |
| 模型不支持结构化输出 | 默认走文本协议（D4） |
| 玩家嫌慢 | 允许"只骰不推演"模式（跳过 agent，只投骰） |
| 与别的扩展抢注入位 | `setExtensionPrompt` 的 key 加扩展前缀，注入深度可配 |
| 切聊天丢状态 | `chatMetadata` + 切聊天前立即 `saveMetadata()` |
| 与酒馆版本演进脱节 | 只用 `getContext()`；`manifest.minimum_client_version` 兜底 |
